C-06 — La revocacion se mide; expulsar exige encender el flag
================================================================================

apps/api/src/security/authorizationState.js
  - authorizationMode() (linea 11): enforce si AUTHORIZATION_VERSION_ENFORCEMENT_ENABLED
    es "true"; observe si solo AUTHORIZATION_VERSION_OBSERVATION_ENABLED; off si ninguna.
  - noteAuthEvent() (linea 32): incrementa total y motivos, emite la metrica y solo
    escribe log por request cuando el modo no es off.
  - validateAuthorization() (linea 87): registra recordMismatch() siempre y lanza 401
    cuando enforcement esta encendido. USER_REVOKED, TENANT_REVOKED y el estado
    ausente se rechazan en cualquier modo: un usuario o tenant desactivado no sigue
    operando durante la observacion.
  - Devuelve authorization_reason y authorization_session_revoke_reason (linea 104)
    para que el refresh pueda distinguir reuso de cierre.

apps/api/src/fabric/metrics.js
  - apex_authorization_mismatch_total{reason} (linea 37), agregado por motivo, sin
    ids, rutas ni payloads. recordAuthorizationMismatch (linea 93) nunca lanza: una
    metrica no puede tumbar una peticion.

A-02 — El refresh rota y el reuso es observable
================================================================================

apps/api/src/modules/auth/service.js
  - refresh() (linea 188): si la sesion llego revocada, registra refresh_token_reused
    cuando el motivo fue refresh_rotated, o refresh_session_revoked cuando fue logout.
  - Si la sesion esta revocada NO se rota (linea 202): rotar ahi lavaria el logout en
    una sesion fresca para quien tenga el refresh; se conserva el sid revocado y se
    devuelve el mismo refresh presentado, sin ganar otros 30 dias.
  - La sesion sana se rota (rotateSession, authorizationState.js:114) y se emite un
    refresh nuevo con jti (service.js:219).

apps/web/lib/sessionSecurity.ts
  - keepSessionAlive guarda el refresh rotado (linea 125). Si no se guardara, el
    cliente conservaria uno viejo y el reuso medido seria un artefacto del cliente.

Pruebas (apps/api/test/auth-session-hardening.test.js):
  - Refresh sano rota la sesion y entrega refresh nuevo. :173
  - Refresh ya rotado: se mide como reuso, no crea sesion nueva ni expulsa. :186
  - Refresh de sesion cerrada por logout se distingue del reuso. :200
  - Con enforcement encendido, ese mismo refresh revocado responde 401. :212

C-07 — trustProxy por allowlist
================================================================================

apps/api/src/security/trustProxy.js (nuevo) + apps/api/server.js:16
  - resolveTrustProxy() (linea 12): vacio, "false", "0", "true" o invalido -> false.
  - Acepta saltos (1..99), IPv4/CIDR, IPv6/CIDR y loopback/linklocal/uniquelocal.

BLOQUEO declarado
================================================================================

CERRADO 2026-11-08: el stack local estaba caido y se levanto con autorizacion del
  propietario. La certificacion E2E de login, renovacion y logout se ejecuto y su
  salida queda arriba.

BLOQUEO: TRUST_PROXY no esta declarado en Railway desde esta intervencion. Mientras
  el ambiente desplegado no lo declare, detras del proxy toda peticion anonima
  comparte la IP del proxy en el limite global (200/min) y en la clave del bloqueo de
  login. Declararlo es cambio de ambiente y exige autorizacion propia. Fallar cerrado
  aqui evita que un XFF falsificado esquive el bloqueo; el costo es la agregacion por
  IP del proxy hasta que se declare.

================================================================================
Limites conocidos y residuales abiertos
================================================================================

L-01 (Informativo) Dos pestanas pueden presentar el mismo refresh: una rota y la otra
  se mide como REFRESH_TOKEN_REUSED sin ataque. En observacion solo se cuenta; con
  enforcement obligaria a re-login. La activacion necesita esa medicion.
L-02 (Informativo) Los access tokens emitidos antes de una rotacion conservan el sid
  anterior; al encender enforcement caducan por revocacion. La ventana se mide antes.
R-04 (Alta) A-01/A-13 siguen abiertos: apps/api/src/security/supabaseAuth.js reactiva
  un usuario desactivado (linea 365) y un tenant suspendido (linea 317-322) al
  sincronizar. No estaba en la opcion autorizada y toca autenticacion global por otro
  camino; requiere autorizacion expresa.
